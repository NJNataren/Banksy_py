# PTMT Hypoxia and Cell-Death-Associated Spatial Marker Analysis

## Status

## Aim

Map the available hypoxia and necrosis/cell-death-associated genes across PTMT
tissue sections and summarize their expression in every BANKSY cell cluster.
The initial analysis should answer:

1. Where are marker-positive cells located within each tissue section?
2. Which BANKSY clusters contain the marker-positive cells?
3. Is expression diffuse, spatially localized, or concentrated at cluster
   boundaries?
4. Do marker patterns differ between the experimental groups after the sample
   metadata and comparison structure have been confirmed?

## Genes Available in the PTMT Panel

Only four genes from the proposed list are present in
`ptmt_combined_xenium_panel_markers.csv`:

| Gene | Working category | Interpretation caution |
|---|---|---|
| `HIF1A` | Hypoxia-associated | HIF1A activity is strongly regulated after transcription, so HIF1A mRNA alone is not a reliable hypoxia score. |
| `IL1A` | Damage/inflammation-associated | A DAMP and inflammatory signal; expression is not specific evidence of necrosis. |
| `IL1B` | Damage/inflammation-associated | Reports inflammatory signalling and may reflect myeloid state rather than necrotic cells directly. |
| `PMAIP1` | Apoptosis/stress-associated | A pro-apoptotic gene and not a direct necrosis marker. |

The figures and filenames should therefore use wording such as
"hypoxia and cell-death-associated markers" rather than claiming a validated
hypoxia or necrosis signature.

## Proposed Analysis

### 1. Input and metadata audit

- Confirm the clean AnnData object for every included sample.
- Confirm that expression will be read from `.raw`, matching the existing
  script 03 summaries, with `.X` used only as an explicitly documented
  fallback.
- Confirm spatial coordinates in `obsm['spatial']` or `obsm['xy']`.
- Confirm the selected BANKSY cluster column and whether reviewed biological
  cluster annotations are available.
- Build an explicit sample metadata table containing run, treatment/group,
  specimen or patient identifier, pairing, and any AMACR-negative subset flag.
  Comparisons must use this table rather than parsing biological groups from
  sample names.
- Report missing genes, missing coordinates, empty clusters, and small
  clusters before plotting.

### 2. Tissue spatial plots

For each sample, create:

- one reference map coloured by the selected BANKSY cluster;
- one cell-level expression map for each of `HIF1A`, `IL1A`, `IL1B`, and
  `PMAIP1`;
- an optional detected/not-detected map for sparse genes, especially `IL1B`;
- a compact four-gene panel using the same tissue extent, orientation, point
  size, and panel dimensions.

Use equal spatial aspect and preserve the Xenium coordinate orientation. Plot
low or zero expression first and high expression last so positive cells remain
visible. Record the colour limits used for every plot.

Two colour-scaling views are useful for different questions:

- within-sample robust scaling, such as zero to the gene's 99th percentile,
  for finding spatial structure within a tissue;
- one shared per-gene scale across samples for honest cross-sample visual
  comparison.

The shared-scale plots should be treated as the comparison figures. The
within-sample plots should be clearly labelled as pattern-discovery views.

### 3. Expression by cell cluster

At the selected resolution, summarize every sample-cluster-gene combination
with:

- number of cells in the cluster;
- mean log-normalized expression;
- median expression if feasible from the cell-level object;
- percentage of cells with expression greater than zero;
- number of expressing cells.

Primary cluster figure: a dotplot with genes on one axis and sample-cluster
rows on the other, using colour for mean expression and dot size for percentage
expressing. Keep the unscaled mean values in the output table. A gene-wise
z-scored version may be added for pattern discovery, but it must not replace
the absolute summary because z-scoring can exaggerate weak signals.

Also produce per-sample cluster dotplots alongside the spatial maps. These make
it possible to connect a spatial expression patch to the cluster or clusters
occupying that region.

### 4. Spatial localization by cluster

After the basic maps are reviewed, quantify whether each gene is spatially
localized within or near particular clusters. Candidate summaries are:

- fraction of expressing cells contributed by each cluster;
- expression enrichment in a cluster relative to the rest of that sample;
- local neighbourhood composition around marker-positive cells;
- distance from marker-positive cells to selected epithelial, immune, or
  stromal clusters, once biological cluster labels are reviewed.

This should be a second stage. It is premature to define a combined hypoxia or
necrosis score from the current four genes because the panel contains only one
hypoxia-associated gene and the three cell-death-associated genes represent
different biological processes.

### 5. Group comparisons

Once the metadata and pairing structure are confirmed, compare cluster-level
and sample-level summaries between the relevant PTMT conditions. Keep sample
as the biological unit for cohort comparisons; cells are not independent
replicates. Where samples are paired, show paired changes rather than only
pooled cell distributions.

Potential endpoints include:

- sample-level percentage of cells expressing each gene;
- cluster-stratified percentage expressing and mean expression;
- epithelial/tumour-restricted summaries if reviewed cell-type labels exist;
- spatial concentration or neighbourhood metrics from the second stage.

These comparisons should initially be descriptive. Statistical testing and
multiple-testing correction can be chosen after confirming sample identity,
pairing, and group sizes.

## Completion Criteria for the First Pass

- All included samples pass a documented input audit.
- Every sample has a cluster reference map and four gene-expression maps.
- Every sample-cluster-gene combination has an exported numerical summary.
- Absolute and z-scored displays are clearly distinguished.
- Missing or weakly detected genes are shown honestly rather than hidden by
  rescaling.
- Group comparisons use verified metadata and samples, not cells, as the
  replicate unit.
- Conclusions remain gene-specific and do not overstate evidence for tissue
  hypoxia or necrosis.

## Session Update (2026-11-10): Standalone Pre-Dotplot QC Script

The agreed workflow position is now:

```text
script 00 clean normalized objects with BANKSY labels
  -> script 02a marker-expression spatial QC and human review
  -> script 03 dotplot summary export
  -> script 04 dotplot rendering
```

The first reviewable draft is:

```text
02a_ptmt_marker_expression_spatial_qc.py
```

The script reads clean clustered AnnData objects directly. Its default
expression source is `.raw.X`, which is a normalized/log1p snapshot in script
00 clean objects, not raw counts. It checks `.raw` against `.X` and compares
binary detection with `layers["counts"]` when the counts layer is available.
It never reads biological expression from BANKSY-expanded spatial objects and
does not renormalize or modify its inputs.

The draft provides:

- full input and expression-source auditing before outputs are written;
- sample- and cluster-level absolute expression and detection summaries;
- robust within-sample and shared per-gene spatial scales;
- BANKSY cluster reference maps, normalized-expression maps, and binary
  detection maps;
- per-sample absolute and gene-wise z-scored cluster QC dotplots;
- cross-sample detection and mean-expression heatmaps;
- a marker-review scaffold with blank `include_for_dotplot`, spatial-pattern,
  QC-note, and reviewer-note fields; and
- `--validate-only`, `--sample`, `--mode`, and `--overwrite` controls.

No automatic inclusion threshold is applied. Marker suitability remains a
human review decision before script 03.

All outputs now default to one self-contained QC package under
`data/xenium/output/<project>/QC/<analysis_name>/`, with `tables/` and
`figures/` subdirectories. The config may override the common `output_root`,
or separately override `output_data_dir` and `output_figure_dir`.

Syntax, CLI startup, validation-only mode, and the complete output path were
tested with a synthetic clean normalized AnnData object in `/tmp`. No real
PTMT AnnData object has been run.
